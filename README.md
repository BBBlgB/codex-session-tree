# Codex 会话树

一个配合 OpenAI Codex 使用的 VS Code 扩展，支持 Windows、Linux 本地窗口，以及 Remote SSH / WSL 工作区窗口。侧栏用树形连线展示会话的分支关系，在编辑区可打开更宽的关系图。点击节点后，通过带有目标窗口路由的 Codex 会话入口打开该会话；悬停约 350 毫秒显示主题、模型和推理强度，移开后隐藏。

支持为节点添加别名、“进行中 / 已完成 / 待验证”标签和多行备注，也可从会话树移除节点。这些信息保存在插件自己的数据中。

## 安装与使用

1. 先切换到希望展示关系图的 VS Code 窗口；例如本地项目窗口，或目标 SSH / WSL 项目窗口。安装 OpenAI 的 Codex 扩展（`openai.chatgpt`），并在工作区所在系统准备 Python 3.10 或更新版本。Windows 默认使用 `py -3`，Linux 使用 `python3`。
2. 在该窗口的扩展菜单中选择 **从 VSIX 安装**，选择 `codex-session-tree-0.6.0.vsix`。远程窗口需要将本扩展安装到远程主机 / WSL 端。若提示重载，请完成后继续。本地安装也可以运行：

   ```powershell
   code --install-extension ./codex-session-tree-0.6.0.vsix
   ```

3. 在目标窗口按 `Ctrl+Shift+P`，执行 **Codex 会话树: 在此窗口打开会话关系图**。面板标题包含工作区名称，界面顶部显示 Windows/Linux、远程主机、当前工作区和会话目录，便于确认环境。侧栏中的展开按钮也仅在它所属的窗口打开关系图。
4. **分支家族**只显示有父子关系的一组会话；**全部会话**同时显示独立会话和关系未知的历史会话。每棵树默认收起，点击标题栏可独立展开或收起，标题栏显示根节点主题和会话数量。搜索会保留命中节点所属的整个家族。可按当前项目、归档状态和子代理筛选。
5. 点击节点切换会话。首次调用时，VS Code 可能询问是否允许 Codex 的 URI 处理器打开链接；这是编辑器自身的确认。可在该提示中选择记住决定。

树中描边的节点表示“最近从本扩展请求打开的会话”。Codex 未提供当前活动会话的公开订阅接口，因此在 Codex 自身界面切换后，描边不会自动跟随。

每棵树的展开状态与节点内的分支折叠状态分别保存，刷新或重新打开视图后恢复。同一视图中的不同 Codex 数据目录分别记录整棵树的展开状态；侧栏和编辑区各自保存自己的状态。

## 快速切换与搜索定位

按 **Ctrl+Alt+J**（macOS 为 **Cmd+Alt+J**），或执行 **Codex 会话树: 快速切换会话**。原生选择列表按“收藏 / 最近从插件打开 / 其他会话”分组，支持搜索原主题、别名、目录、标签、备注和研究记录，选中后回车切换。点击条目右侧星标可收藏或取消收藏；预览窗口也提供收藏按钮。收藏和最近打开记录保存在插件自己的数据中，并按 Codex 数据目录隔离。列表包含可打开的归档会话，排除已移除及历史不可用的记录。

树内搜索会自动展开命中节点及其祖先路径，高亮关键词并显示命中数量；即使处于“分支家族”模式，也会显示命中的独立会话。按 **Enter / Shift+Enter** 或搜索框下方的箭头定位下一条 / 上一条。搜索期间手动折叠只影响本次搜索，清空搜索后恢复原有折叠状态。搜索范围是元数据和插件记录，不包含聊天正文；项目、归档、子代理和已移除筛选仍然生效。

## 会话预览与分支对照

点击节点下方的 **预览**，查看最近用户问题、最近最终回复（旧记录缺少最终标记时会说明）、已记录的文件变更，以及插件备注。可展开长原文与来源，直接选择复制文本，或点击 **继续会话**。预览按需读取，**刷新原文**会重新读取历史。最近问题与最近回复可能属于不同轮次。

在两个节点下分别点击 **加入对照**，再点击上方 **对照**。支持跨家族选择，宽窗口并排展示，窄侧栏上下排列。对照包括原文摘录、文件列表、标签、备注，以及手动填写的 **目标 / 结论 / 待验证问题**；后面三个字段在节点编辑框的“研究记录”中填写，每项最多 6000 字符。仅依据已有关系显示最近共同祖先，不推断缺失的分支关系，也不自动生成研究结论。

原文读取支持旧 JSONL 与 `thread_history_1.sqlite` 的分页历史；分页会话优先读取分页数据库，避免使用过期的旧文件。JSONL 预览检查末尾 8 MiB，分页预览检查最近 300 条对话及文件变更记录；单条摘录最多 60,000 字符，最多展示 20 个历史文件路径。读取范围不足或消息截断时显示提示。来源包含 JSONL 字节位置或分页记录的 turn/item ID。文件列表表示历史中记录的路径，不保证当前文件仍存在；JSONL 只提取明确的 `apply_patch` 路径，分页历史提取 `fileChange` 路径。

收藏、预览和对照均无需模型或 API key。历史记录以只读方式访问，研究记录保存在插件中；不支持的历史结构或读取错误会明确显示，切换数据目录会关闭旧预览并清空待对照选择。

## 别名、标签与备注

点击节点右上角的 **✎**，即可在插件内编辑：

- **别名**：最多 120 个字符；保存后作为节点标题显示，悬停卡片仍保留原主题。留空即可恢复显示原主题。
- **标签**：可勾选“进行中”“已完成”“待验证”，支持多选，直接显示在节点上。
- **备注**：支持多行，最多 6000 个字符。保存后节点显示备注标记，悬停预览；再次打开编辑框可查看完整内容。
- **研究记录**：目标、结论和待验证问题，每项支持多行、最多 6000 个字符，在预览和对照中展示，也参与搜索。

搜索同时匹配原主题、别名、标签、备注和研究记录。**取消**不保存本次修改；**清空字段**后点击**保存**，可移除该节点的文字记录和标签，收藏状态另行保存。

这些信息保存在 VS Code 提供给本扩展的 `globalState` 中，按 Codex 数据目录和会话 ID 隔离。同一环境、同一 VS Code 配置文件内的其他工作区可读取同一份信息，重新打开和升级扩展后保留。SSH / WSL 使用对应扩展运行环境的存储；本功能不启用设置同步。不会修改 Codex 的原主题、历史文件或数据库。清除 VS Code 中本扩展的数据会一并清除这些信息。

## 移除与恢复节点

点击节点右上角的 **×**，可将该节点从插件的会话树中移除。此操作仅保存插件内的隐藏状态，**不会删除或归档 Codex 会话，也不会修改会话文件和数据库**。刷新、重新打开和升级扩展后，移除状态仍保留；原有别名、标签和备注也会保留。

勾选顶部的 **显示已移除** 可查看这些节点，再点击节点右上角的 **↶** 恢复。侧栏与编辑区同步更新。

移除父节点只影响该节点，子节点继续显示，并标注“父节点已移除”；它们会单独成组，不会把祖孙关系改画成直接父子关系。在“分支家族”中，因移除节点而剩余的单节点也会保留。搜索不会命中已移除节点，除非勾选“显示已移除”。

## 窗口与运行环境

通过在目标窗口执行命令来指定窗口。本扩展不枚举和遥控其他已打开窗口。旧版不带目标窗口信息的 `vscode://local-tools.codex-session-tree/open` 全局链接已移除，避免由系统猜测应打开的窗口。

| 当前窗口 | 索引脚本运行位置 | 默认数据目录 |
| --- | --- | --- |
| Windows 本地项目 | 本机 Windows | 该环境的 `CODEX_HOME` 或用户目录下 `.codex` |
| Linux 本地项目 | 本机 Linux | 该环境的 `CODEX_HOME` 或 `~/.codex` |
| Remote SSH 项目 | SSH 远程主机 | 远程用户的 `CODEX_HOME` 或 `~/.codex` |
| WSL 项目 | 对应 WSL 发行版 | Linux 用户的 `CODEX_HOME` 或 `~/.codex` |

扩展以 `workspace` 类型运行；只在 Windows 本地安装不会让远程窗口自动获得这个未发布的本地 VSIX。可用 **Developer: Show Running Extensions** 核实运行位置。如果在 Windows 本地窗口启用了 Codex 的“在 WSL 中运行”选项，会话树会提示改在 WSL 工作区窗口打开，避免读取另一环境的会话。

机器路径设置需在对应环境配置。若 SSH / WSL 窗口继承了 Windows 的路径，请在 **远程设置**中清空或设置该环境的 `codexHome`、`pythonPath`。目录支持 `~/`，不接受跨系统路径。具体安装方式参见 [VS Code 远程扩展文档](https://code.visualstudio.com/api/advanced-topics/remote-extensions#installing-a-development-version-of-your-extension)。

## 数据与兼容范围

- 只读工作区运行环境的 `CODEX_HOME` 或 `~/.codex` 下的 `state_*.sqlite`、`session_index.jsonl`、会话 JSONL 和预览所需的 `thread_history_1.sqlite`。使用 SQLite 只读连接读取实时数据库，关闭连接后结束读取；不复制 WAL、不更新数据库、不改写历史。
- 用户分支来自明确的 `session_meta.forked_from_id`。子代理派生关系单独标识，默认隐藏。旧会话缺少原始关系记录时显示“关系未知”，不按相似标题或相似内容猜测。
- 模型和强度优先使用数据库最近保存的字段；字段缺失时读取会话尾部最近的 `turn_context`。无记录则显示“未记录”。这不是整个会话所有轮次的模型清单，也不是对尚未发送的输入框设置的实时读取。
- 会话原始文件可能因 Codex 的分页存储迁移而不再存在。本扩展保留数据库中的索引。对于缺少可访问历史的记录，按钮会说明无法切换。
- 当前项目筛选按会话工作目录与打开的工作区目录匹配：Windows 兼容盘符大小写、分隔符和扩展路径前缀；Linux 保留大小写及合法的反斜杠字符。若祖先被筛选隐藏，会保留淡色的祖先节点以呈现关系。
- 仅在视图可见时定期读取，默认每 10 秒刷新。无需 API key，无联网请求，不调用模型。
- 各窗口读取其工作区所在环境的会话，不跨机器汇总；支持桌面 VS Code，本版不提供纯浏览器扩展。
- 点击跳转使用 `vscode://openai.chatgpt/local/<会话 ID>`（Insiders 自动使用对应 scheme），先经 `vscode.env.asExternalUri` 附加窗口路由，并完整保留返回值。已核对 Windows Codex **26.901.22334** 和 Linux Codex **26.51007.21434** 的 URI 处理器和 `/local/:conversationId` 路由。这是现有扩展内部路由，未来 Codex 更新可能需要适配；本扩展不会修改 Codex 安装文件。

## 设置

在设置中搜索 `codexSessionTree`：

| 设置 | 用途 |
| --- | --- |
| `codexSessionTree.codexHome` | 指定工作区所在环境的 Codex 数据目录，默认自动发现 |
| `codexSessionTree.pythonPath` | 指定工作区所在环境的 Python 3 可执行文件路径 |
| `codexSessionTree.refreshSeconds` | 自动刷新间隔，默认 10 秒 |

## 开发与验证

```powershell
git clone https://github.com/BBBlgB/codex-session-tree.git
cd codex-session-tree
npm ci --ignore-scripts
npm test
npm run test:python
npx playwright install chromium
node test/browser.js
node test/run-host.js
npm run package
```

上述命令可用于 Windows PowerShell 和 Linux shell；开发依赖需要 Node.js 22 或更新版本。Linux 无桌面显示的环境可用 `xvfb-run -a node test/run-host.js` 运行宿主测试（需安装 Xvfb 和 VS Code 所需系统库）。

浏览器测试使用 `test/fixtures/sessions.json` 中的虚构会话，扩展宿主测试使用临时生成的虚构会话目录和指定测试工作区，均不读取个人会话。截图和测试输出保存在忽略目录 `artifacts/`，不上传仓库或打入安装包。扩展宿主测试使用独立下载的 VS Code 1.141.2 和隔离用户目录，也可通过 `VSCODE_EXECUTABLE` 指定现有可执行文件路径。

可选执行 `node --test test/codex-contract.local.js`，检查本机已安装 Codex 扩展的内部 URI 路由。此检查依赖具体 Codex 版本；未安装时跳过。

仓库仅包含代码、文档、依赖锁文件与虚构测试数据，不包含个人会话、真实截图、数据库、凭据或本机验证记录。`.gitignore` 已排除这些开发产物。`publisher: local-tools` 是本地 VSIX 的扩展标识，不代表已发布到 VS Code Marketplace。

相关接口依据：[VS Code Webview API](https://code.visualstudio.com/api/extension-guides/webview)、[VS Code URI Handler](https://code.visualstudio.com/api/references/vscode-api#window.registerUriHandler)。
